# Cambio Labs Grant Writing & Opportunity Scouting

This skill has two modes. Figure out which one the request needs (sometimes both) before doing anything else:

1. **Draft mode** — someone needs grant application / LOI / funder-questionnaire language written or refined.
2. **Scout mode** — someone needs help finding, scoring, or logging a prospective funder or opportunity.

Both modes lean on the same three grounding sources, in priority order:

- **Live Google Drive**: the `****WINS & PEER REVIEWED` folder — Cambio Labs' actual past applications, organized by program area. This is the best source of truth because it's real, funder-reviewed language, not a generic template. See `references/drive-map.md` for the folder layout and which funders live where.
- **Live Notion** (when connected): the "Prospecting List" database (funder pipeline) and "Social Media Planner" database (public-facing storytelling and partner mentions). If Notion isn't connected in this session, don't block on it — say so once, then fall back to the bundled references below, or ask the person to paste the relevant Notion content.
- **Bundled starter kit** (`references/vetted-language.md`, `references/funding-priorities.md`, `references/prospecting-workflow.md`) — curated snapshots pulled from the sources above in August 2026. Use these when live access isn't available, or as a quick-reference alongside live search. They will drift out of date; when live Drive or Notion content conflicts with the bundled snapshot, trust the live source.

Whichever sources you use, say so briefly at the end of your output (e.g. "Pulled org history from the Kellogg LOI and stats from the Sept 2025 org one-pager" or "Notion wasn't connected, so I used the bundled funding-priorities snapshot") — the team needs to know how fresh the grounding was, since multiple people use this skill and won't all have the same connectors enabled.

## Before drafting or scouting: check what's already there

Cambio Labs has been applying to grants for years and the "Wins & Peer Reviewed" folder is organized specifically so this doesn't have to start from scratch. Before writing anything new:

- Search the Drive folder for the **same funder** first (a repeat funder like TD Bank, Moelis, or NBA Foundation may have prior submissions worth reusing almost verbatim) — see the Google Drive search patterns in `references/drive-map.md`.
- If it's a new funder, search by **program area** (Youth Entrepreneurship, Adult Entrepreneurship, Tech, Organizational) for the closest match in focus.
- Check the "Checklist" doc in that folder — it tracks which past applications are marked "Reviewed" (safe to reuse language from) versus still pending review.

Cambio's own past applications sometimes include an internal section (marked "INTERNAL — NOT PART OF APPLICATION") with their own reasoning for why they're a strong fit for that specific funder, before the actual answers. This is a genuinely good practice — when drafting for a new or competitive opportunity, consider writing this kind of internal fit rationale first (clearly labeled so it's never mistaken for submission content), then draft the actual answers from it. It forces the mission-alignment argument to be explicit rather than vague.

## Draft mode

**1. Understand the ask.** Get (or ask for) the funder's actual questions, word/character limits, and deadline. If someone just says "draft our LOI for X," ask what the funder's actual prompt/questions are if not provided — don't invent a generic template when a real one might exist.

**2. Gather grounding.** Search Drive (and Notion if connected) per the section above. Pull the closest-matching past language: mission/history, population served, track record, relevant program description, financials/eligibility facts. `references/vetted-language.md` has a curated set of these blocks if live search comes up short or as a sanity check.

**3. Write in Cambio's voice**, not a generic nonprofit voice. This voice comes from Cambio's own drafting practice ("Grant Buddy"):

- Lead with reasoning, briefly. Before answering a substantive question, note in a line or two why this framing fits — then answer. Don't pad this; it's a sentence or two, not a preamble.
- Always tie the answer back to Cambio's actual mission (combating systemic poverty through education, technology, social entrepreneurship, and workforce access for BIPOC and low-income communities) and to *this specific funder's* stated priorities — don't write generic mission language that could apply to any nonprofit.
- Blend a concrete story or example with hard numbers. Cambio's strongest past applications do both — a named program or participant outcome, plus a stat (cohorts delivered, learners reached, dollars awarded, income growth). Don't use one without the other if both are available.
- Structure for a busy reviewer: short paragraphs, headers or bold section labels matching the funder's own question numbering, bullets only where the funder's form uses them.
- Never invent a statistic, partner name, quote, or outcome. If a number isn't in Drive, Notion, or what the user told you, ask rather than guessing — grant fraud/misrepresentation risk is real and Cambio's credibility depends on every submitted number being defensible.
- Respect stated word/character limits exactly — funders enforce these, and an answer that's cut off mid-sentence at submission is worse than a tight one.
- If there are multiple questions, answer all of them in one pass, clearly labeled by number, rather than one at a time — this is faster for the team to review.

**4. Verify every specific claim before showing anyone the draft.** This is the step most likely to get skipped under time pressure, and it's the one that matters most — a fabricated detail in a submitted grant application is a real reputational and legal risk for Cambio, not just a stylistic flaw. Go back through the draft and, for every named partner, specific number, quote, location count, or outcome, confirm it traces to an actual source (a specific Drive doc, Notion row, or something the user told you directly in this conversation) rather than something that sounds plausible given the surrounding context. Two failure modes to watch for specifically, because they're easy to fall into without noticing:
  - **Don't upgrade a vague true statement into a specific false one.** If a source says "270 entrepreneurs engaged across community workshops," don't write "270 entrepreneurs across 11 sites in five boroughs" — the site count and borough count weren't in the source, even though they feel like a natural elaboration.
  - **Don't confuse "similar organizations a funder has supported" with "Cambio's own partners."** The Prospecting List's "Similar Orgs They've Supported" column lists *other* nonprofits a given funder has backed (used to argue fit), not organizations Cambio itself works with — pulling one of those names into a sentence like "our partner X is requesting year-round programming" is a fabrication even though the org name itself is real.
  If you can't verify a specific detail, either cut it, replace it with the vaguer-but-true version of the same point, or flag it inline (e.g. `[CONFIRM: exact workshop count]`) so a human catches it before submission — don't silently smooth it into confident prose.

**5. Output.** Default to creating a **Google Doc** (via the Google Drive connector) titled `[Funder Name] – [Grant/Program Name] Draft`, so it's immediately shareable and commentable by the team. If Google Drive isn't connected in this session, draft in the chat instead and say so. Ask the user if there's a specific Drive folder it should land in (e.g. inside the relevant program-area subfolder of Wins & Peer Reviewed, once it's actually won) — otherwise create it in the user's Drive root and share the link.

**6. Close the loop.** Remind the user (don't just do it silently) that once this is submitted, it should get logged in the Prospecting List (status → "Submitted!") and that if it's eventually won, it's worth adding to the Wins & Peer Reviewed folder for the next person who applies to a similar funder.

## Scout mode

**1. Understand the ask.** Is this "is funder X a good fit?", "find me new opportunities," or "help me log/prioritize what's already in the pipeline"? Each needs a slightly different pass.

**2. Score against Cambio's actual fundraising strategy**, not generic nonprofit-fundraising heuristics. Cambio has a specific tiered strategy (`references/funding-priorities.md` has the full breakdown, pulled from the "2026 Fundraising North Star"):

| Tier | Typical ask | Focus |
|---|---|---|
| Hyperlocal quick wins | $5,000–$25,000 | NYC community grants, local banks, corporate giving, NYCHA opportunities, participatory budgeting |
| Unrestricted / capacity building | $25,000–$100,000 | General operating support, staffing, systems, technology, evaluation |
| Strategic foundations | $75,000–$250,000 | Economic mobility, BIPOC entrepreneurship, workforce development, AI, digital equity, youth opportunity |

For any opportunity, work out which tier it fits (by ask size and focus), whether it duplicates something already in the pipeline, and whether the ask amount is realistic given Cambio's current operating budget (check the latest figure in Drive or ask — this has changed year to year, don't assume an old figure is current).

**3. Cross-check the pipeline.** If Notion's Prospecting List is connected, search it before recommending anything as "new" — Cambio already tracks funders with a rating (1–5), category, ask amount, deadline, similar orgs funded, program fit tags, and a status pipeline (Needs Review → For Team Consideration → Recommended by Team → Outlined → Draft in Progress → Submitted → Won/Lost, plus Pre-Application Reach Out and Apply Next Year). Full schema in `references/prospecting-workflow.md`. Don't re-suggest something already marked "Lost" without noting that history, or something already "Won" as if it were unclaimed.

**4. Give a structured recommendation**, not just a vibe check: funder name, category, which tier it fits, ask range, focus alignment (spell out *why*, referencing Cambio's specific programs — Startup NYCHA, Cambio Solar, Social Entrepreneurship Incubator, Cambio Coding & AI/Journey platform — not generic alignment language), deadline if known, and a suggested fit rating using the same 1–5 scale the team already uses.

**5. Offer to log it.** If Notion is connected, offer to add a new row to the Prospecting List with the fields above. If not, produce the row as a clean table the person can paste in themselves, and say that's what you're doing.

## When live connectors aren't available

Google Drive and Notion are personal connectors — each team member needs their own enabled (and needs the Wins & Peer Reviewed folder shared with them) for this skill to pull live content for *them*, even though the skill itself is shared. If a teammate is missing one:

- No Google Drive: fall back entirely to `references/vetted-language.md` and say so clearly — don't present bundled-snapshot language as if it were freshly pulled.
- No Notion: fall back to `references/funding-priorities.md` and `references/prospecting-workflow.md`, and mention that pipeline status may be stale since the live tracker wasn't checked.
- Neither: still help — draft or scout using the bundled references — but flag plainly that this used the static snapshot, not live data, so the person knows to double check specifics before submitting anything.
